# Level, CR and Rank Range Filters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add from/to range filtering by CR, creature level, spell level and spell rank to the Bestiary & Grimoire browser, without conflating the corpus's four separate numeric scales.

**Architecture:** A single `SCALES` table declares the four scales (which records each governs, how to read a record's value, how to label it). Filtering, control construction and control visibility all read from that table. Filter state joins the existing `F` object. Each record is tested only against its own scale, so CR and creature level never interact.

**Tech Stack:** Vanilla JS and CSS in one file (`app.template.html`). No libraries, no build step beyond `build_bundles.py`. Python 3 for verification oracles.

## Global Constraints

- **Edit `app.template.html` only. Never edit `index.html`** — it is overwritten by every build.
- **No external assets.** No CDN scripts, fonts, or images. The built page must work offline from a `file://` URL.
- **`app.template.html` uses LF line endings.** Do not convert to CRLF. (`build_bundles.py` and the converters use CRLF — do not touch them here.)
- **Four build anchors in `app.template.html` must survive verbatim**, or `build_bundles.py` will fail:
  - `<title>Bestiary &amp; Grimoire</title>`
  - `<p id="lmsg">Loading data files…</p>`
  - `</main>\n\n<script>\n"use strict";`
  - `async function boot(){\n`
- **No new colours.** Use existing tokens only: `--stone`, `--hair`, `--ink`, `--dim`, `--faint`, `--gilt`, `--mono`.
- **Rebuild after every change:** `python build_bundles.py`
- **This repo has no test runner.** There is no pytest, no jest, no npm. Verification is: compute an expected count in Python directly from the bundles (the oracle), then drive the UI in a browser and assert the displayed count matches. Every task below gives the exact oracle command and its expected output.

Replace it with:

```js
const F = { kind:new Set(), sys:new Set(), extra:new Set(), range:{} };

/* The corpus carries four separate numeric scales. CR 15 is not Creature 15,
   so each scale filters only its own records and they never interact.
   Pathfinder focus spells share the rank scale: they are numbered 1-10 exactly
   as ranks are, and the FOCUS chip already isolates them as a category. */
const SCALES = [
  { key:"cr5e",   label:"D&D 5e · CR",
    applies: r => r._kind === "monster" && r.gameSystem === "dnd5e",
    valueOf: r => r.challenge.value,
    labelOf: r => r.challenge.display },
  { key:"lvlPf",  label:"Pathfinder 2e · Creature level",
    applies: r => r._kind === "monster" && r.gameSystem === "pf2e",
    valueOf: r => r.challenge.value,
    labelOf: r => String(r.challenge.value) },
  { key:"spl5e",  label:"D&D 5e · Spell level",
    applies: r => r._kind === "spell" && r.gameSystem === "dnd5e",
    valueOf: r => r.level.value,
    labelOf: r => String(r.level.value) },
  { key:"rankPf", label:"Pathfinder 2e · Rank",
    applies: r => r._kind === "spell" && r.gameSystem === "pf2e",
    valueOf: r => r.level.value,
    labelOf: r => String(r.level.value) },
];

function scaleFor(r){
  for (const s of SCALES) if (s.applies(r)) return s;
  return null;
}

function passRange(r){
  const s = scaleFor(r);
  if (!s) return true;                       // no scale governs this record
  const g = F.range[s.key];
  if (!g) return true;                       // control not built, so inactive
  const v = s.valueOf(r);
  if (v == null) return true;                // never hide a record for lacking a value
  return v >= g.from && v <= g.to;
}
```

```js
/* Options come from the loaded records, not hardcoded bounds, so a future book
   that adds CR 31 extends the control on its own. */
function buildRangeControls(){
  const host = $("#f-range");
  for (const s of SCALES){
    const seen = new Map();                  // value -> label
    for (const r of DATA)
      if (s.applies(r)){
        const v = s.valueOf(r);
        if (v != null && !seen.has(v)) seen.set(v, s.labelOf(r));
      }
    if (seen.size < 2) continue;             // nothing to range over
    const vals = [...seen.keys()].sort((a,b) => a - b);

    F.range[s.key] = { from: vals[0], to: vals[vals.length - 1] };

    const box = document.createElement("div");
    box.className = "rng";
    box.dataset.scale = s.key;
    const opts = vals.map(v => `<option value="${v}">${esc(seen.get(v))}</option>`).join("");
    box.innerHTML =
      `<span class="lbl">${esc(s.label)}</span>` +
      `<div class="row">` +
        `<select data-end="from" aria-label="${esc(s.label)} from">${opts}</select>` +
        `<span class="to">to</span>` +
        `<select data-end="to" aria-label="${esc(s.label)} to">${opts}</select>` +
      `</div>`;
    host.appendChild(box);

    const [selFrom, selTo] = box.querySelectorAll("select");
    selTo.value = String(vals[vals.length - 1]);
    selFrom.onchange = selTo.onchange = e => {
      const g = F.range[s.key];
      g[e.target.dataset.end] = Number(e.target.value);
      // an empty range cannot be created by accident: push the other end along
      if (g.from > g.to){
        if (e.target.dataset.end === "from"){ g.to = g.from; selTo.value = String(g.to); }
        else { g.from = g.to; selFrom.value = String(g.from); }
      }
      refresh();
    };
  }
}
```

```js
/* Driven by the chip filters only — not by the query and not by the ranges
   themselves. A range matching nothing must keep its control on screen, or
   there is no way to widen it again. */
function updateRangeVisibility(chipped){
  for (const s of SCALES){
    const box = document.querySelector(`.rng[data-scale="${s.key}"]`);
    if (box) box.hidden = !chipped.some(r => s.applies(r));
  }
}
```
